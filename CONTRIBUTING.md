# Contributing to SOLID Agents

Thank you for your interest in contributing! 🚀  
This repository is both an **open-source framework** and an **open research project** exploring how SOLID principles apply to multi-agent LLM systems.

We welcome contributions in the form of bug reports, feature suggestions, code, experiments, documentation, or research discussions.

---

## How to Contribute

### 1. Reporting Issues
- Use the [GitHub Issues](../../issues) tab to report bugs, request features, or ask questions.
- Please include:
  - A clear title and description
  - Steps to reproduce (if reporting a bug)
  - Expected vs. actual behavior
  - Relevant logs, screenshots, or error messages

### 2. Suggesting Features or Research Directions
- Label your issue with **`enhancement`** or **`research-idea`**.
- Provide context: Why is this valuable? How does it connect to SOLID principles or agent architectures?

### 3. Submitting Code
- Fork the repo and create a new branch (`feature/your-feature-name` or `fix/your-bug-name`).
- Write clear, modular code following the repository’s architecture (agents should respect **Single Responsibility** whenever possible).
- Include or update **tests** when applicable.
- Submit a **pull request (PR)** with:
  - A descriptive title
  - A summary of changes
  - Any relevant issue numbers (e.g., `Closes #12`)

### 4. Documentation
- Improvements to docs, diagrams, or examples are very welcome.
- Research writeups (e.g., comparisons, literature summaries) can be added under `docs/` or `notebooks/`.

---

## Code Style

- Python: follow [PEP8](https://peps.python.org/pep-0008/).  
- Use docstrings (`"""..."""`) to explain modules, classes, and functions.  
- Keep functions and agents **focused on one responsibility** (aligning with SRP).  

---

## Research Etiquette

- Cite sources in `RESEARCH.md` or notebooks when drawing from papers, repos, or blog posts.  
- Clearly mark any datasets you contribute (with attribution + license).  
- Avoid adding proprietary or private data.  

---

## Community Guidelines

This project follows the [Code of Conduct](CODE_OF_CONDUCT.md).  
By contributing, you agree to uphold a respectful, inclusive environment.
